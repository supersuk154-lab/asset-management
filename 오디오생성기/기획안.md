# 오디오생성기 기획안 — 대본 기반 다화자 대화 MP3 자동 생성기 (무료 버전)

> **v1.0 (2026-07-18)**
> 제약 조건: ① 유료 API 사용 금지 ② 클로드 코드(Claude Code)를 파이프라인의 두뇌로 사용

---

## 1. 목표

사용자가 텍스트 대본(예: `A: 안녕? / B: 오랜만이야!`)을 넣으면,
두 명 이상의 화자가 번갈아 말하는 **하나의 자연스러운 MP3 파일**을 자동 생성한다.

- 입력: 대본 텍스트 파일 (`input/대본.txt`)
- 출력: 완성된 대화 음성 (`output/대본.mp3`)
- 실행: 클로드 코드에게 "이 대본 음성으로 만들어줘" 한마디로 전체 파이프라인 구동

---

## 2. 원본 타당성 보고서 대비 변경점

원본 보고서는 Typecast / ElevenLabs 등 유료 API를 핵심 엔진으로 권장했다.
본 기획은 **유료 API 금지** 제약에 따라 아래와 같이 대체한다.

| 보고서의 유료 구성 | 본 기획의 무료 대체 | 비고 |
|---|---|---|
| Typecast SSFM-v30 (감정 추론) | **클로드 코드가 감정 분석** → 속도·피치 파라미터로 변환 | LLM 추론을 무료 자원(클로드 코드 세션)으로 해결 |
| ElevenLabs Dialogue API (다화자 병합) | **pydub 직접 병합** (WAV 중간처리 → 최종 1회 MP3 인코딩) | 보고서 5장 방법론 그대로 채택 |
| 정규식 파서 모듈 | 정규식 파서 **+ 클로드 코드 보조 파싱** | 불규칙한 대본도 클로드가 JSON으로 정리 |
| 유료 TTS 음성 | **edge-tts** (1차) / **MeloTTS** (2차) | 아래 3장 비교 참조 |

유지하는 핵심 원칙 (보고서에서 그대로 계승):
- 모든 중간 처리는 **WAV(무손실)** 로 하고, **최종 출력 시 단 1회만 MP3 인코딩** → 접합부 팝핑 노이즈 방지
- 화자 교대 시 **동적 무음(500~1000ms)** 삽입으로 대화 호흡 재현
- 대본 → **구조화된 JSON**(화자/감정/대사) 변환을 파이프라인의 첫 단계로 고정

## 3. 무료 TTS 엔진 비교 및 선정

| 후보 | 비용 | 한국어 | 다화자 | 설치 난이도 | GPU | 판정 |
|---|---|---|---|---|---|---|
| **edge-tts** | 무료 (API 키 불필요) | ◎ (SunHi·InJoon·Hyunsu 등 다수) | ◎ 보이스 교체로 구현 | pip 한 줄 | 불필요 | ✅ **1차 채택** |
| MeloTTS | 무료 (MIT, 로컬) | ○ | △ 화자 수 제한 | 중간 | CPU 가능 | 🔜 2차 (오프라인 필요 시) |
| XTTS v2 | 무료 (비상업 CPML) | ○ (17개 언어) | ◎ 보이스 클로닝 | 높음 | 권장 | 보류 (라이선스·사양) |
| Kokoro | 무료 (Apache) | ✕ (한국어 미지원) | △ | 중간 | CPU 가능 | 제외 |
| gTTS | 무료 | ○ | ✕ (단일 음색) | 쉬움 | 불필요 | 제외 (화자 구분 불가) |

**edge-tts 선정 근거:**
- 완전 무료이며 API 키·회원가입이 필요 없다 (인터넷 연결만 필요)
- 한국어 네이티브 보이스가 여러 개라 화자별로 다른 목소리 배정이 바로 가능
- `rate`(속도), `pitch`(높낮이), `volume` 파라미터를 지원 → 감정 표현의 최소 단위 확보
- 한계: Typecast급 연기(웃음소리·한숨 합성)는 불가 → 클로드의 감정→파라미터 매핑과 무음 연출로 보완

## 4. 시스템 아키텍처

```
[사용자] 대본.txt 를 input/ 에 저장 → 클로드 코드에게 실행 요청
    ↓
[Step 1: 파싱]  scripts/parse_script.py  (+ 클로드 코드 보조)
    - 정규식으로 "화자: 대사" 패턴 분리, [감정] 지시문 추출
    - 정규식이 실패하는 불규칙 대본 → 클로드 코드가 직접 읽고 JSON 작성
    - 출력: work/dialogue.json
    ↓
[Step 2: 감정 → 파라미터 변환]  클로드 코드 (판단·추론 담당)
    - 각 대사의 감정/문맥 분석 → rate·pitch·화자간 무음 길이 결정
    - 출력: work/dialogue.json 의 각 항목에 tts_params 필드 추가
    ↓
[Step 3: 음성 합성]  scripts/synthesize.py
    - edge-tts 호출: 화자별 보이스(voices.json 매핑) + 파라미터 적용
    - 대사 1건 = WAV 1개 → work/segments/001.wav, 002.wav ...
    ↓
[Step 4: 병합 + 인코딩]  scripts/merge_audio.py
    - pydub: WAV 조각 + 동적 무음 삽입 순차 결합 (전 과정 무손실)
    - 완성된 단일 오디오를 최종 1회만 MP3(192kbps~320kbps)로 export
    - 출력: output/{대본이름}.mp3
    ↓
[Step 5: 검증]  클로드 코드
    - 대사 수 == 세그먼트 수 확인, 총 길이 출력, 파일 존재 확인
```

**역할 분담 (자산관리 프로젝트와 동일 철학):**
- **클로드 코드 (AI의 영역):** 대본 이해, 감정 추론, 파라미터 결정, 파이프라인 지휘, 오류 시 자가 수정
- **파이썬 (시스템의 영역):** 정규식 파싱, TTS 호출, 오디오 신호 처리, 파일 입출력 강제

## 5. 폴더 구조

```
오디오생성기/
├── 기획안.md                ← 현재 문서
├── CLAUDE.md                ← 클로드 코드용 실행 지침서 (Phase 1에서 작성)
├── requirements.txt         ← edge-tts, pydub (+ ffmpeg 시스템 설치 필요)
├── voices.json              ← 화자 이름 → edge-tts 보이스 매핑
│                               예: {"A": "ko-KR-InJoonNeural", "B": "ko-KR-SunHiNeural"}
├── scripts/
│   ├── parse_script.py      ← Step 1: 대본 → dialogue.json
│   ├── synthesize.py        ← Step 3: edge-tts 합성 (async 병렬 처리)
│   ├── merge_audio.py       ← Step 4: pydub 병합 + MP3 인코딩
│   └── pipeline.py          ← Step 1~4 일괄 실행 CLI
├── input/                   ← 사용자가 넣는 대본 .txt
├── work/                    ← 중간 산출물 (dialogue.json, segments/*.wav) — git 제외
└── output/                  ← 최종 .mp3 — git 제외
```

**dialogue.json 스키마 (예시):**

```json
{
  "title": "샘플대화",
  "lines": [
    {
      "seq": 1,
      "speaker": "A",
      "emotion": "반갑게",
      "text": "야, 진짜 오랜만이다!",
      "tts_params": { "rate": "+10%", "pitch": "+2Hz" },
      "pause_after_ms": 600
    },
    {
      "seq": 2,
      "speaker": "B",
      "emotion": null,
      "text": "그러게... 몇 년 만이지?",
      "tts_params": { "rate": "-5%", "pitch": "-1Hz" },
      "pause_after_ms": 800
    }
  ]
}
```

## 6. 단계별 개발 계획

### Phase 1 — MVP (최우선)
- [ ] 폴더 구조 및 `requirements.txt` 생성, ffmpeg 확인
- [ ] `parse_script.py`: "화자: 대사" 기본 패턴 + `[감정]` 태그 정규식 파싱
- [ ] `voices.json`: 화자 2인 기본 매핑 (남/여 보이스)
- [ ] `synthesize.py`: edge-tts로 대사별 WAV 생성
- [ ] `merge_audio.py`: 고정 무음(700ms) 삽입 병합 → MP3 1회 인코딩
- [ ] `pipeline.py`: 위 단계를 명령 하나로 실행
- [ ] 샘플 대본으로 엔드투엔드 테스트 (실제 MP3 생성 확인)

**Phase 1 완료 기준:** `python scripts/pipeline.py input/샘플.txt` 실행 시 두 화자의 목소리가 번갈아 나오는 MP3가 output/에 생성된다.

### Phase 2 — 자연스러움 고도화
- [ ] `CLAUDE.md` 작성: 클로드 코드가 감정 분석 → `tts_params`·`pause_after_ms`를 대사별로 동적 결정하는 워크플로 정착
- [ ] 문맥 기반 무음 가변화 (질문 뒤 짧게, 화제 전환 시 길게)
- [ ] 말줄임표(...)·대시(-) 등 구두점 연출 가이드를 클로드 파싱 규칙에 반영
- [ ] 3인 이상 다화자 지원, 화자별 기본 톤 프로필(voices.json 확장)
- [ ] 크로스페이드/오버레이 옵션 (말 겹침 연출)

### Phase 3 — 확장 (선택)
- [ ] MeloTTS 로컬 엔진 추가 (오프라인 모드, 인터넷 불필요)
- [ ] 배경음악(BGM) 트랙 오버레이 + 볼륨 덕킹
- [ ] 대본 없이 주제만 주면 클로드가 대본 작성 → 음성화까지 원스톱

## 7. 리스크 및 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| edge-tts는 비공식 무료 서비스 (정책 변경 가능) | 파이프라인 중단 | TTS 호출부를 `synthesize.py` 한 곳에 격리 → 엔진 교체가 한 파일 수정으로 끝나게 설계. Phase 3의 MeloTTS가 백업 |
| edge-tts 감정 표현 한계 (웃음·한숨 불가) | 자연스러움 저하 | rate/pitch/무음 연출로 근사. 감정 태그는 JSON에 보존해 두어 향후 상위 엔진 도입 시 즉시 활용 |
| ffmpeg 미설치 환경 | MP3 인코딩 실패 | pipeline.py 시작 시 ffmpeg 존재 검사 → 설치 안내 메시지 출력 (Fail-Fast) |
| 대본 형식이 제각각 | 파싱 실패 | 정규식 실패 시 클로드 코드가 원문을 직접 읽어 dialogue.json 수동 생성 (자가 수정 루프) |
| 상업적 이용 | 라이선스 문제 | edge-tts 산출물의 상업적 이용은 MS 약관상 회색지대 → 상용화 시점에 유료 API 또는 MIT 라이선스 MeloTTS로 전환 검토 |
